1)
Camada Web e CargaInicial
Básico
Na v0.1.0 a aplicação sobe, roda o CommandLineRunner da classe principal e encerra. Transforme o projeto em uma aplicação web que fica no ar esperando requisições, e tire a carga de dados da classe principal.
Requisitos
  • Adicionar a dependência spring-boot-starter-web no pom.xml
  • Criar config/CargaInicial: @Component que implementa CommandLineRunner, recebe UsuarioRepository e EtiquetaRepository pelo construtor e executa o antigo carregarDados()
  • Deixar a TaskmanagerApiApplication apenas com o main
  • Rodar o projeto (F6 no NetBeans) e confirmar no console que o Tomcat subiu na porta 8080
Solução
<!-- pom.xml --> <dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-web</artifactId> </dependency>
package br.org.irede.taskmanagerapi.config; import br.org.irede.taskmanagerapi.model.*; import br.org.irede.taskmanagerapi.repository.EtiquetaRepository; import br.org.irede.taskmanagerapi.repository.UsuarioRepository; import java.time.LocalDate; import org.springframework.boot.CommandLineRunner; import org.springframework.stereotype.Component; @Component public class CargaInicial implements CommandLineRunner { private final UsuarioRepository usuarioRepository; private final EtiquetaRepository etiquetaRepository; public CargaInicial(UsuarioRepository usuarioRepository, EtiquetaRepository etiquetaRepository) { this.usuarioRepository = usuarioRepository; this.etiquetaRepository = etiquetaRepository; } @Override public void run(String... args) { Etiqueta estudo = etiquetaRepository.save(new Etiqueta("Estudo")); Etiqueta trabalho = etiquetaRepository.save(new Etiqueta("Trabalho")); Etiqueta urgente = etiquetaRepository.save(new Etiqueta("Urgente")); Usuario ana = new Usuario("Ana Souza", "ana@email.com", "123456"); Tarefa t1 = new Tarefa("Estudar JPA", "Revisar @Entity e @Id", Prioridade.ALTA); t1.setPrazo(LocalDate.of(2026, 11, 5)); t1.adicionarEtiqueta(estudo); t1.adicionarEtiqueta(urgente); ana.adicionarTarefa(t1); // ... demais tarefas da Ana, do Bruno e do Leo, iguais ao carregarDados() da v0.1.0 usuarioRepository.save(ana); // cascade ALL salva as tarefas // usuarioRepository.save(bruno); usuarioRepository.save(leo); } }

2)
TarefaController com GET e @JsonIgnore
Básico
Crie o primeiro controlador REST do Task Manager, com as duas operações de leitura, e teste no Postman. Antes, prepare as entidades para virar JSON sem erro.
Requisitos
  • TarefaController no pacote controller, com @RestController e URI base /api/v1/tarefas
  • TarefaRepository injetado pelo construtor
  • GET /api/v1/tarefas lista todas; GET /api/v1/tarefas/{id} busca uma com @PathVariable
  • @JsonIgnore em Tarefa.usuario e em Etiqueta.tarefas
  • Requisições "Listar tarefas" e "Buscar tarefa" na coleção do Postman, usando a variável {{baseUrl}}
Solução
package br.org.irede.taskmanagerapi.controller; import br.org.irede.taskmanagerapi.model.Tarefa; import br.org.irede.taskmanagerapi.repository.TarefaRepository; import java.util.List; import org.springframework.web.bind.annotation.GetMapping; import org.springframework.web.bind.annotation.PathVariable; import org.springframework.web.bind.annotation.RequestMapping; import org.springframework.web.bind.annotation.RestController; @RestController @RequestMapping("/api/v1/tarefas") public class TarefaController { private final TarefaRepository repository; public TarefaController(TarefaRepository repository) { this.repository = repository; } @GetMapping public List<Tarefa> listar() { return repository.findAll(); } @GetMapping("/{id}") public Tarefa buscarPorId(@PathVariable Long id) { return repository.findById(id).orElse(null); } }

3)
POST, PUT e DELETE com @RequestBody
Intermediário
Complete o CRUD seguindo o slide "Refatorando o Controlador": receber o JSON com @RequestBody e usar os métodos do repositório. Como toda tarefa precisa de um dono e usuario está oculto no JSON, o id do usuário vem na URI.
Requisitos
  • Injetar também o UsuarioRepository pelo construtor
  • POST /api/v1/tarefas?usuarioId={id}: @RequestBody Tarefa + @RequestParam Long usuarioId; liga a tarefa ao usuário e salva
  • PUT /api/v1/tarefas/{id}: substitui todos os campos editáveis (título, descrição, prioridade, prazo, concluída)
  • DELETE /api/v1/tarefas/{id}: remove com deleteById
  • As três requisições na coleção do Postman
Solução
// TarefaController.java (imports: UsuarioRepository e org.springframework.web.bind.annotation.*) private final TarefaRepository repository; private final UsuarioRepository usuarioRepository; public TarefaController(TarefaRepository repository, UsuarioRepository usuarioRepository) { this.repository = repository; this.usuarioRepository = usuarioRepository; } @PostMapping public Tarefa criar(@RequestBody Tarefa tarefa, @RequestParam Long usuarioId) { tarefa.setUsuario(usuarioRepository.findById(usuarioId).orElseThrow()); return repository.save(tarefa); // Salva no banco! } @PutMapping("/{id}") public Tarefa atualizar(@PathVariable Long id, @RequestBody Tarefa dados) { Tarefa tarefa = repository.findById(id).orElseThrow(); tarefa.setTitulo(dados.getTitulo()); tarefa.setDescricao(dados.getDescricao()); tarefa.setPrioridade(dados.getPrioridade()); tarefa.setPrazo(dados.getPrazo()); tarefa.setConcluida(dados.isConcluida()); return repository.save(tarefa); } @DeleteMapping("/{id}") public void remover(@PathVariable Long id) { repository.deleteById(id); }
Postman: POST {{baseUrl}}/tarefas?usuarioId=1
Body (raw → JSON): { "titulo": "Testar a API no Postman", "prazo": "2026-11-19", "prioridade": "ALTA" } HTTP/1.1 200 OK ← criou, mas o status ainda não diz isso Content-Type: application/json { "id": 9, "titulo": "Testar a API no Postman", "descricao": null, "concluida": false, "prazo": "2026-11-19", "prioridade": "ALTA", "etiquetas": [ ] }
💡 No Postman, escolha Body → raw → JSON (isso envia o cabeçalho Content-Type: application/json; sem ele, a resposta é 415 Unsupported Media Type). Problemas que ficam para a próxima questão: o POST responde 200 em vez de 201, o DELETE responde 200 em vez de 204, e um id inexistente no PUT ou no POST (orElseThrow) vira 500 Internal Server Error.
4)
Status Corretos com ResponseEntity
Intermediário
Aplique a boa prática do slide "O status HTTP dá semântica à resposta": troque o retorno de todos os métodos (menos o listar) para ResponseEntity e devolva o status certo em cada situação.
Requisitos
  • GET /{id}: 200 com a tarefa ou 404 sem corpo
  • POST: 201 Created com a tarefa criada, ou 404 se o usuarioId não existir
  • PUT /{id}: 200 com a tarefa atualizada, ou 404
  • DELETE /{id}: 204 No Content, ou 404
Solução
// TarefaController.java (imports: org.springframework.http.HttpStatus e ResponseEntity) @GetMapping("/{id}") public ResponseEntity<Tarefa> buscarPorId(@PathVariable Long id) { return repository.findById(id) .map(ResponseEntity::ok) .orElse(ResponseEntity.notFound().build()); } @PostMapping public ResponseEntity<Tarefa> criar(@RequestBody Tarefa tarefa, @RequestParam Long usuarioId) { Usuario usuario = usuarioRepository.findById(usuarioId).orElse(null); if (usuario == null) { return ResponseEntity.notFound().build(); } tarefa.setUsuario(usuario); return ResponseEntity.status(HttpStatus.CREATED).body(repository.save(tarefa)); } @PutMapping("/{id}") public ResponseEntity<Tarefa> atualizar(@PathVariable Long id, @RequestBody Tarefa dados) { return repository.findById(id) .map(tarefa -> { tarefa.setTitulo(dados.getTitulo()); tarefa.setDescricao(dados.getDescricao()); tarefa.setPrioridade(dados.getPrioridade()); tarefa.setPrazo(dados.getPrazo()); tarefa.setConcluida(dados.isConcluida()); return ResponseEntity.ok(repository.save(tarefa)); }) .orElse(ResponseEntity.notFound().build()); } @DeleteMapping("/{id}") public ResponseEntity<Void> remover(@PathVariable Long id) { if (repository.findById(id).isEmpty()) { return ResponseEntity.notFound().build(); } repository.deleteById(id); return ResponseEntity.noContent().build(); }

💡 .map(ResponseEntity::ok) transforma o Optional<Tarefa> em Optional<ResponseEntity<Tarefa>>; se ele estiver vazio, o orElse entra com o 404. O ResponseEntity<Void> do DELETE deixa claro que a resposta não tem corpo. Rode o DELETE da tarefa 8 duas vezes: a segunda resposta é 404, porque ela já não existe.
5)
Validação com @Valid e Coleção Completa
Avançado
"Nunca confie na entrada do usuário." Proteja o POST e o PUT com Bean Validation, seguindo o exemplo do slide (nome → titulo, preço → prioridade), e feche a coleção do Postman com os casos de erro.
Requisitos
  • Adicionar spring-boot-starter-validation no pom.xml
  • titulo: @NotBlank ("O título é obrigatório") e @Size(min = 3) ("O título deve ter no mínimo 3 caracteres")
  • prioridade: @NotNull ("A prioridade é obrigatória")
  • @Valid antes do @RequestBody no criar e no atualizar
  • Na coleção, uma requisição "Criar tarefa inválida" que recebe 400, e exportar a coleção (Collection v2.1)
Solução
<!-- pom.xml --> <dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-validation</artifactId> </dependency>
// Tarefa.java import jakarta.validation.constraints.NotBlank; import jakarta.validation.constraints.NotNull; import jakarta.validation.constraints.Size; @NotBlank(message = "O título é obrigatório") @Size(min = 3, message = "O título deve ter no mínimo 3 caracteres") @Column(nullable = false, length = 100) private String titulo; @NotNull(message = "A prioridade é obrigatória") @Enumerated(EnumType.STRING) private Prioridade prioridade = Prioridade.MEDIA;

💡 O título "Ok" passa no @NotBlank, mas não no @Size(min = 3): cada anotação é uma regra independente. Com "prioridade": null no JSON, o valor padrão MEDIA é sobrescrito por null, e o @NotNull barra. Se o campo simplesmente não vier no JSON, o padrão MEDIA continua valendo. O Hibernate também valida essas anotações antes de cada INSERT, então a carga inicial precisa respeitá-las (e respeita: todos os títulos têm 3+ caracteres). As mensagens no corpo da resposta chegam na aula 09.

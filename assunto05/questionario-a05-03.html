Erros Padronizados e DTOs no Task Manager 5 questões Nível Básico a Avançado

Reproduza, passo a passo, o que as aulas 09 e 10 entregam no taskmanager-api: respostas com o status certo, a exceção ResourceNotFoundException, o GlobalExceptionHandler com ErrorResponse (aula 09) e os DTOs de usuário e de tarefa com mapeamento manual (aula 10). O ponto de partida é o TarefaController do fim da aula 08 (CRUD em /api/v1/tarefas, com @Valid). Cada questão parte do código da anterior. Tente resolver por conta própria e depois revele a solução para conferir.

0/5
reveladas
1)
201 com Location e DELETE com existsById
Básico
Aplique as duas refatorações dos slides "POST (Criar): Retornando 201 Created" e "DELETE (Deletar): Retornando 204 No Content" no TarefaController.
Requisitos
  • No criar, guardar o retorno do save em tarefaSalva e montar a URI com URI.create("/api/v1/tarefas/" + tarefaSalva.getId())
  • Responder com ResponseEntity.created(location).body(tarefaSalva)
  • No remover, verificar com repository.existsById(id): 404 se não existir, 204 depois de apagar
  • No Postman, conferir o cabeçalho Location na aba Headers
Solução
// TarefaController.java (imports: java.net.URI, org.springframework.http.ResponseEntity) @PostMapping public ResponseEntity<Tarefa> criar(@Valid @RequestBody Tarefa tarefa, @RequestParam Long usuarioId) { Usuario usuario = usuarioRepository.findById(usuarioId).orElse(null); if (usuario == null) { return ResponseEntity.notFound().build(); } tarefa.setUsuario(usuario); Tarefa tarefaSalva = repository.save(tarefa); // Boa prática: Retornar a URI do novo recurso no cabeçalho "Location" URI location = URI.create("/api/v1/tarefas/" + tarefaSalva.getId()); return ResponseEntity.created(location).body(tarefaSalva); // Retorna 201 Created } @DeleteMapping("/{id}") public ResponseEntity<Void> remover(@PathVariable Long id) { if (!repository.existsById(id)) { return ResponseEntity.notFound().build(); // Retorna 404 se não existir } repository.deleteById(id); return ResponseEntity.noContent().build(); // Retorna 204 No Content }
Postman: POST {{baseUrl}}/tarefas?usuarioId=1
HTTP/1.1 201 Created Location: /api/v1/tarefas/9 Content-Type: application/json Date: Tue, 24 Nov 2026 22:05:41 GMT { "id": 9, "titulo": "Revisar exceções", "descricao": "Criar o GlobalExceptionHandler", "concluida": false, "prazo": "2026-11-26", "prioridade": "ALTA", "etiquetas": [ ] }
💡 O existsById faz um select count(*) leve, sem carregar a tarefa. Ele é necessário porque, no Spring Data 3, deleteById com um id inexistente não faz nada e não avisa: sem a verificação, o DELETE da tarefa 99 responderia 204. Na coleção do Postman, salve o POST com um teste que confere o status 201.
2)
A Exceção Customizada ResourceNotFoundException
Básico
"Crie exceções claras que representem seus erros de negócio." Crie a ResourceNotFoundException e refatore o buscarPorId do controlador para lançá-la, como no slide "Exceções Customizadas". Depois teste no Postman: o que acontece com o id 99?
Requisitos
  • Pacote novo br.org.irede.taskmanagerapi.exception
  • ResourceNotFoundException estendendo RuntimeException, com construtor (String message) que chama super(message)
  • buscarPorId retornando Tarefa e usando orElseThrow com a mensagem "Tarefa com id " + id + " não encontrada"
Solução
package br.org.irede.taskmanagerapi.exception; public class ResourceNotFoundException extends RuntimeException { public ResourceNotFoundException(String message) { super(message); } }
// TarefaController.java @GetMapping("/{id}") public Tarefa buscarPorId(@PathVariable Long id) { // Código limpo! Focado na regra de negócio. return repository.findById(id) .orElseThrow(() -> new ResourceNotFoundException("Tarefa com id " + id + " não encontrada")); }
Postman: GET {{baseUrl}}/tarefas/99
HTTP/1.1 500 Internal Server Error Content-Type: application/json Date: Tue, 24 Nov 2026 22:09:12 GMT { "timestamp": "2026-11-24T22:09:12.338+00:00", "status": 500, "error": "Internal Server Error", "path": "/api/v1/tarefas/99" } // console do servidor: ERROR ... [dispatcherServlet] : Servlet.service() ... threw exception [Request processing failed: br.org.irede.taskmanagerapi.exception.ResourceNotFoundException: Tarefa com id 99 não encontrada] with root cause
💡 Ainda é 500, e está certo que seja: para o Spring, a ResourceNotFoundException é só mais uma RuntimeException. O ganho até aqui é o código limpo e uma exceção com nome e mensagem que dizem o que aconteceu. Quem a traduz para 404 é o @ControllerAdvice da próxima questão. Como ela é unchecked, o buscarPorId não precisa de throws.
3)
ErrorResponse e GlobalExceptionHandler (404 e 400)
Intermediário
Feche a aula 09: centralize o tratamento com @ControllerAdvice e devolva sempre o mesmo corpo de erro, o ErrorResponse. Aproveite para tirar a "contaminação" dos outros métodos: todos passam a lançar a exceção em vez de montar o 404.
Requisitos
  • ErrorResponse (pacote exception) com timestamp (LocalDateTime), status, erro, mensagem e caminho, construtor e getters
  • GlobalExceptionHandler com @ControllerAdvice e dois @ExceptionHandler: ResourceNotFoundException → 404 e MethodArgumentNotValidException → 400 com as mensagens dos campos
  • criar (usuário inexistente), atualizar e remover lançando ResourceNotFoundException
  • Na coleção: "Buscar tarefa inexistente" (404) e "Criar tarefa inválida" (400) agora com corpo
Solução
package br.org.irede.taskmanagerapi.exception; import java.time.LocalDateTime; public class ErrorResponse { private LocalDateTime timestamp; private int status; private String erro; private String mensagem; private String caminho; public ErrorResponse(int status, String erro, String mensagem, String caminho) { this.timestamp = LocalDateTime.now(); this.status = status; this.erro = erro; this.mensagem = mensagem; this.caminho = caminho; } // getters de todos os campos (o Jackson usa os getters para gerar o JSON) }
package br.org.irede.taskmanagerapi.exception; import jakarta.servlet.http.HttpServletRequest; import java.util.stream.Collectors; import org.springframework.http.HttpStatus; import org.springframework.http.ResponseEntity; import org.springframework.web.bind.MethodArgumentNotValidException; import org.springframework.web.bind.annotation.ControllerAdvice; import org.springframework.web.bind.annotation.ExceptionHandler; @ControllerAdvice public class GlobalExceptionHandler { // Captura nossa exceção customizada e a traduz para um 404 @ExceptionHandler(ResourceNotFoundException.class) public ResponseEntity<ErrorResponse> handleNotFound(ResourceNotFoundException ex, HttpServletRequest request) { ErrorResponse erro = new ErrorResponse(HttpStatus.NOT_FOUND.value(), "Não encontrado", ex.getMessage(), request.getRequestURI()); return ResponseEntity.status(HttpStatus.NOT_FOUND).body(erro); } // Falhas do @Valid viram 400 com a mensagem de cada campo @ExceptionHandler(MethodArgumentNotValidException.class) public ResponseEntity<ErrorResponse> handleValidacao(MethodArgumentNotValidException ex, HttpServletRequest request) { String mensagem = ex.getBindingResult().getFieldErrors().stream() .map(e -> e.getField() + ": " + e.getDefaultMessage()) .collect(Collectors.joining("; ")); ErrorResponse erro = new ErrorResponse(HttpStatus.BAD_REQUEST.value(), "Dados inválidos", mensagem, request.getRequestURI()); return ResponseEntity.badRequest().body(erro); } }
// TarefaController.java — os métodos só fazem a regra e lançam a exceção @PostMapping public ResponseEntity<Tarefa> criar(@Valid @RequestBody Tarefa tarefa, @RequestParam Long usuarioId) { Usuario usuario = usuarioRepository.findById(usuarioId) .orElseThrow(() -> new ResourceNotFoundException("Usuário com id " + usuarioId + " não encontrado")); tarefa.setUsuario(usuario); Tarefa tarefaSalva = repository.save(tarefa); URI location = URI.create("/api/v1/tarefas/" + tarefaSalva.getId()); return ResponseEntity.created(location).body(tarefaSalva); } @PutMapping("/{id}") public Tarefa atualizar(@PathVariable Long id, @Valid @RequestBody Tarefa dados) { Tarefa tarefa = repository.findById(id) .orElseThrow(() -> new ResourceNotFoundException("Tarefa com id " + id + " não encontrada")); tarefa.setTitulo(dados.getTitulo()); tarefa.setDescricao(dados.getDescricao()); tarefa.setPrioridade(dados.getPrioridade()); tarefa.setPrazo(dados.getPrazo()); tarefa.setConcluida(dados.isConcluida()); return repository.save(tarefa); // 200 OK é o padrão } @DeleteMapping("/{id}") public ResponseEntity<Void> remover(@PathVariable Long id) { if (!repository.existsById(id)) { throw new ResourceNotFoundException("Tarefa com id " + id + " não encontrada"); } repository.deleteById(id); return ResponseEntity.noContent().build(); }

💡 O mesmo handler serve o PUT /tarefas/99, o DELETE /tarefas/99 e o POST ?usuarioId=99 (mensagem "Usuário com id 99 não encontrado"), sem uma linha a mais. O timestamp sai no horário do servidor (Fortaleza, UTC-3), enquanto o cabeçalho Date é sempre GMT. O Spring injeta o HttpServletRequest no handler só por ele estar na lista de parâmetros.

UsuarioDTO e Mapeamento Manual
Intermediário
Aula 10: reproduza o slide "Entidade (Banco) vs. DTO (API)" com o Usuario do Task Manager. Crie o UsuarioDTO sem a senha e um endpoint para consultá-lo, convertendo a entidade na mão, como no slide "Mapeamento Manual".
Requisitos
  • Pacote novo dto com o POJO UsuarioDTO: id, nome, email (sem senha, sem tarefas), getters e setters
  • UsuarioController com GET /api/v1/usuarios/{id} devolvendo UsuarioDTO
  • Método privado converterParaDto(Usuario usuario)
  • Id inexistente lança ResourceNotFoundException (o handler da questão 3 cuida do 404)
  • Requisições "Buscar usuário" e "Buscar usuário inexistente" na coleção do Postman
Solução

package br.org.irede.taskmanagerapi.controller; import br.org.irede.taskmanagerapi.dto.UsuarioDTO; import br.org.irede.taskmanagerapi.exception.ResourceNotFoundException; import br.org.irede.taskmanagerapi.model.Usuario; import br.org.irede.taskmanagerapi.repository.UsuarioRepository; import org.springframework.web.bind.annotation.*; @RestController @RequestMapping("/api/v1/usuarios") public class UsuarioController { private final UsuarioRepository repository; public UsuarioController(UsuarioRepository repository) { this.repository = repository; } @GetMapping("/{id}") public UsuarioDTO buscarPorId(@PathVariable Long id) { Usuario usuario = repository.findById(id) .orElseThrow(() -> new ResourceNotFoundException("Usuário com id " + id + " não encontrado")); return converterParaDto(usuario); } private UsuarioDTO converterParaDto(Usuario usuario) { UsuarioDTO dto = new UsuarioDTO(); dto.setId(usuario.getId()); dto.setNome(usuario.getNome()); dto.setEmail(usuario.getEmail()); return dto; } }

TarefaDTO na Entrada e na Saída, sem @JsonIgnore
Avançado
Feche a aula 10 seguindo o fluxo do slide: JSON → Controller → TarefaDTO (validado) → entidade → Repository, e o caminho inverso na saída. O TarefaController passa a receber e devolver apenas TarefaDTO, e as entidades perdem o @JsonIgnore.
Requisitos
  • POJO TarefaDTO: id, titulo, descricao, prioridade, prazo, concluida e usuarioId, com as validações (@NotBlank/@Size no título, @NotNull na prioridade e no usuarioId)
  • As anotações de validação saem da entidade Tarefa; o @JsonIgnore sai de Tarefa.usuario e de Etiqueta.tarefas
  • No controlador, métodos privados converterParaDto(Tarefa) e copiarParaEntidade(TarefaDTO, Tarefa)
  • O POST recebe o dono no corpo ("usuarioId": 1) em vez de ?usuarioId=1
  • Atualizar a coleção do Postman e exportá-la (Collection v2.1)
Solução
package br.org.irede.taskmanagerapi.dto; import br.org.irede.taskmanagerapi.model.Prioridade; import jakarta.validation.constraints.NotBlank; import jakarta.validation.constraints.NotNull; import jakarta.validation.constraints.Size; import java.time.LocalDate; public class TarefaDTO { private Long id; @NotBlank(message = "O título é obrigatório") @Size(min = 3, message = "O título deve ter no mínimo 3 caracteres") private String titulo; private String descricao; @NotNull(message = "A prioridade é obrigatória") private Prioridade prioridade; private LocalDate prazo; private boolean concluida; @NotNull(message = "O usuário é obrigatório") private Long usuarioId; // getters e setters }

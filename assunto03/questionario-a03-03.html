Massa de Dados e as Primeiras Consultas com @Query
Básico
Para testar consultas, o banco precisa de dados variados. Ajuste o run da TaskmanagerApiApplication para gravar 2 usuários e 7 tarefas com prazos, prioridades e status diferentes. Depois, escreva as duas primeiras consultas JPQL do TarefaRepository.
Requisitos
  • Um método auxiliar nova(titulo, prioridade, concluida, prazo, dono) no runner, que cria, liga ao usuário e salva a tarefa
  • listarPendentes(): @Query com SELECT t FROM Tarefa t WHERE t.concluida = false
  • buscarPorPrioridade(prioridade, concluida): @Query com os parâmetros nomeados :prioridade e :concluida e @Param
  • Imprimir no console o título das tarefas devolvidas pelas duas consultas
Solução
package br.org.irede.taskmanagerapi.repository; import br.org.irede.taskmanagerapi.model.Prioridade; import br.org.irede.taskmanagerapi.model.Tarefa; import java.util.List; import org.springframework.data.jpa.repository.JpaRepository; import org.springframework.data.jpa.repository.Query; import org.springframework.data.repository.query.Param; public interface TarefaRepository extends JpaRepository<Tarefa, Long> { @Query("SELECT t FROM Tarefa t WHERE t.concluida = false") List<Tarefa> listarPendentes(); @Query("SELECT t FROM Tarefa t WHERE t.prioridade = :prioridade AND t.concluida = :concluida") List<Tarefa> buscarPorPrioridade(@Param("prioridade") Prioridade prioridade, @Param("concluida") boolean concluida); }

JOIN, JOIN FETCH e ORDER BY
Básico
Use as relações mapeadas no assunto 02 dentro das consultas. Liste as tarefas de um usuário (pelo e-mail) já com o usuário carregado, em ordem de prazo, e as tarefas que têm uma determinada etiqueta.
Requisitos
  • listarPorUsuario(email): JOIN FETCH t.usuario, filtro por u.email e ORDER BY t.prazo
  • listarPorEtiqueta(nome): JOIN t.etiquetas e com filtro por e.nome
  • No runner, imprimir titulo → nome do usuário das tarefas da Ana e conferir no console que saiu um único SELECT
Solução
// TarefaRepository — novos métodos @Query("SELECT t FROM Tarefa t JOIN FETCH t.usuario u WHERE u.email = :email ORDER BY t.prazo") List<Tarefa> listarPorUsuario(@Param("email") String email); @Query("SELECT t FROM Tarefa t JOIN t.etiquetas e WHERE e.nome = :nome") List<Tarefa> listarPorEtiqueta(@Param("nome") String nome);
// run() — depois da massa de dados System.out.println("====== Tarefas da Ana"); tarefaRepository.listarPorUsuario("ana@email.com") .forEach(t -> System.out.println(t.getTitulo() + " → " + t.getUsuario().getNome()));

Agregação com GROUP BY e uma Consulta em SQL Nativo
Intermediário
Feche a aula 05 com duas consultas diferentes: um resumo de quantas tarefas existem por prioridade (JPQL com COUNT) e uma busca por termo que ignora maiúsculas e minúsculas usando o ILIKE do PostgreSQL (SQL nativo).
Requisitos
  • contarPorPrioridade(): SELECT t.prioridade, COUNT(t) ... GROUP BY t.prioridade ORDER BY t.prioridade, retornando List<Object[]>
  • buscarPorTermoNativo(termo): @Query com nativeQuery = true sobre a tabela tarefas
  • No runner, imprimir PRIORIDADE: quantidade e o resultado de buscarPorTermoNativo("jp")
Solução
// TarefaRepository — novos métodos @Query("SELECT t.prioridade, COUNT(t) FROM Tarefa t GROUP BY t.prioridade ORDER BY t.prioridade") List<Object[]> contarPorPrioridade(); @Query(value = "SELECT * FROM tarefas WHERE titulo ILIKE CONCAT('%', :termo, '%')", nativeQuery = true) List<Tarefa> buscarPorTermoNativo(@Param("termo") String termo);
// run() System.out.println("====== Tarefas por prioridade"); for (Object[] linha : tarefaRepository.contarPorPrioridade()) { Prioridade prioridade = (Prioridade) linha[0]; Long quantidade = (Long) linha[1]; System.out.println(prioridade + ": " + quantidade); } System.out.println("====== Busca nativa por 'jp'"); tarefaRepository.buscarPorTermoNativo("jp").forEach(t -> System.out.println(t.getTitulo()));

💡 Na agregação não sai SELECT de usuários: a consulta devolve valores, não entidades. Cada Object[] traz os itens na ordem do SELECT ([0] = prioridade, [1] = quantidade); o COUNT é sempre Long. A ordem é ALTA, BAIXA, MEDIA porque o enum é gravado como texto. Na busca nativa, "jp" encontra "JPA" e "JPQL" graças ao ILIKE. Em JPQL, com LIKE, nada seria encontrado.

Busca com Filtros Dinâmicos (Criteria API)
Avançado
Aula 06: implemente o buscaDinamica do slide 11 para tarefas. Como a Criteria precisa do EntityManager, o código fica em uma implementação customizada que o Spring Data "cola" no TarefaRepository. Assim, o resto do projeto continua chamando tudo por tarefaRepository.
Requisitos
  • Interface TarefaRepositoryCustom com List<Tarefa> buscaDinamica(String titulo, LocalDate prazoMin, Prioridade prioridade)
  • Classe TarefaRepositoryCustomImpl (o sufixo Impl é obrigatório) com EntityManager injetado por @PersistenceContext
  • Um Predicate por filtro preenchido: like no título, greaterThanOrEqualTo no prazo, equal na prioridade
  • TarefaRepository passa a estender também TarefaRepositoryCustom
  • Testar com buscaDinamica(null, LocalDate.of(2026, 11, 12), Prioridade.ALTA)
Solução
package br.org.irede.taskmanagerapi.repository; import br.org.irede.taskmanagerapi.model.Prioridade; import br.org.irede.taskmanagerapi.model.Tarefa; import java.time.LocalDate; import java.util.List; public interface TarefaRepositoryCustom { List<Tarefa> buscaDinamica(String titulo, LocalDate prazoMin, Prioridade prioridade); }
package br.org.irede.taskmanagerapi.repository; import br.org.irede.taskmanagerapi.model.Prioridade; import br.org.irede.taskmanagerapi.model.Tarefa; import jakarta.persistence.EntityManager; import jakarta.persistence.PersistenceContext; import jakarta.persistence.criteria.CriteriaBuilder; import jakarta.persistence.criteria.CriteriaQuery; import jakarta.persistence.criteria.Predicate; import jakarta.persistence.criteria.Root; import java.time.LocalDate; import java.util.ArrayList; import java.util.List; public class TarefaRepositoryCustomImpl implements TarefaRepositoryCustom { @PersistenceContext private EntityManager em; @Override public List<Tarefa> buscaDinamica(String titulo, LocalDate prazoMin, Prioridade prioridade) { CriteriaBuilder cb = em.getCriteriaBuilder(); CriteriaQuery<Tarefa> cq = cb.createQuery(Tarefa.class); Root<Tarefa> root = cq.from(Tarefa.class); List<Predicate> predicates = new ArrayList<>(); if (titulo != null && !titulo.trim().isEmpty()) { predicates.add(cb.like(root.get("titulo"), "%" + titulo + "%")); } if (prazoMin != null) { predicates.add(cb.greaterThanOrEqualTo(root.get("prazo"), prazoMin)); } if (prioridade != null) { predicates.add(cb.equal(root.get("prioridade"), prioridade)); } // Combina todos os predicados da lista com "AND" cq.where(predicates.toArray(new Predicate[0])); return em.createQuery(cq).getResultList(); } }

Paginação: do setFirstResult ao Page<Tarefa>
Avançado
Feche a aula 06 (e o Marco 1) com a paginação. Primeiro, o método do slide 10 com setFirstResult/setMaxResults. Depois, uma versão da busca dinâmica que recebe um Pageable e devolve um Page<Tarefa>, que traz a página e também o total de registros.
Requisitos
  • buscarTarefasPaginado(int pagina, int tamanhoPagina), igual ao slide (página começando em 1, ORDER BY t.prazo DESC)
  • Page<Tarefa> buscaDinamica(titulo, prazoMin, prioridade, Pageable pageable) com os mesmos filtros da questão 4
  • Extrair a montagem dos predicados para um método privado montarPredicados, usado pela consulta da página e pela de contagem
  • Ordenação vinda do Pageable (QueryUtils.toOrders), OFFSET/FETCH com getOffset()/getPageSize() e total com cb.count(...)
  • Testar com PageRequest.of(1, 3, Sort.by("prazo")) e sem filtros
Solução
// TarefaRepositoryCustom — novas assinaturas List<Tarefa> buscarTarefasPaginado(int pagina, int tamanhoPagina); Page<Tarefa> buscaDinamica(String titulo, LocalDate prazoMin, Prioridade prioridade, Pageable pageable);
// TarefaRepositoryCustomImpl — novos imports import org.springframework.data.domain.Page; import org.springframework.data.domain.PageImpl; import org.springframework.data.domain.Pageable; import org.springframework.data.jpa.repository.query.QueryUtils; // Slide 10: paginação com JPQL (página começa em 1) @Override public List<Tarefa> buscarTarefasPaginado(int pagina, int tamanhoPagina) { String jpql = "SELECT t FROM Tarefa t ORDER BY t.prazo DESC"; int primeiroResultado = (pagina - 1) * tamanhoPagina; return em.createQuery(jpql, Tarefa.class) .setFirstResult(primeiroResultado) .setMaxResults(tamanhoPagina) .getResultList(); } // A busca da questão 4 passa a usar o método auxiliar @Override public List<Tarefa> buscaDinamica(String titulo, LocalDate prazoMin, Prioridade prioridade) { CriteriaBuilder cb = em.getCriteriaBuilder(); CriteriaQuery<Tarefa> cq = cb.createQuery(Tarefa.class); Root<Tarefa> root = cq.from(Tarefa.class); cq.where(montarPredicados(cb, root, titulo, prazoMin, prioridade)); return em.createQuery(cq).getResultList(); } // Busca dinâmica paginada @Override public Page<Tarefa> buscaDinamica(String titulo, LocalDate prazoMin, Prioridade prioridade, Pageable pageable) { CriteriaBuilder cb = em.getCriteriaBuilder(); // 1. consulta da página: filtros + ordenação + OFFSET/FETCH CriteriaQuery<Tarefa> cq = cb.createQuery(Tarefa.class); Root<Tarefa> root = cq.from(Tarefa.class); cq.where(montarPredicados(cb, root, titulo, prazoMin, prioridade)); cq.orderBy(QueryUtils.toOrders(pageable.getSort(), root, cb)); List<Tarefa> conteudo = em.createQuery(cq) .setFirstResult((int) pageable.getOffset()) .setMaxResults(pageable.getPageSize()) .getResultList(); // 2. consulta de contagem: mesmos filtros, sem ordem e sem página CriteriaQuery<Long> cqCount = cb.createQuery(Long.class); Root<Tarefa> rootCount = cqCount.from(Tarefa.class); cqCount.select(cb.count(rootCount)) .where(montarPredicados(cb, rootCount, titulo, prazoMin, prioridade)); Long total = em.createQuery(cqCount).getSingleResult(); return new PageImpl<>(conteudo, pageable, total); } private Predicate[] montarPredicados(CriteriaBuilder cb, Root<Tarefa> root, String titulo, LocalDate prazoMin, Prioridade prioridade) { List<Predicate> predicates = new ArrayList<>(); if (titulo != null && !titulo.trim().isEmpty()) { predicates.add(cb.like(root.get("titulo"), "%" + titulo + "%")); } if (prazoMin != null) { predicates.add(cb.greaterThanOrEqualTo(root.get("prazo"), prazoMin)); } if (prioridade != null) { predicates.add(cb.equal(root.get("prioridade"), prioridade)); } return predicates.toArray(new Predicate[0]); }
// run() — imports: org.springframework.data.domain.{Page, PageRequest, Sort} Page<Tarefa> pagina = tarefaRepository.buscaDinamica(null, null, null, PageRequest.of(1, 3, Sort.by("prazo"))); System.out.println(pagina); pagina.getContent().forEach(t -> System.out.println(t.getPrazo() + " " + t.getTitulo())); System.out.println("total=" + pagina.getTotalElements() + " paginas=" + pagina.getTotalPages());

💡 PageRequest.of(1, 3) é a segunda página (o Spring começa em 0), por isso getOffset() = 3. O Root pertence a uma consulta: a contagem precisa do seu próprio rootCount, e é por isso que os predicados são montados por um método reaproveitável. Quando dois registros têm o mesmo prazo (aqui, 12/11), o banco pode devolvê-los em qualquer ordem. Para uma paginação estável, desempate com um segundo critério: Sort.by("prazo", "id"). Este Page volta na aula 12, quando a paginação chega à API REST.

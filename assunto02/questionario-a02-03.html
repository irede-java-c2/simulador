Projeto Spring Boot com Tarefa e Prioridade
Básico
Crie o projeto no Spring Initializr (Maven, Java 25, Spring Boot 3.5.x, br.org.irede / taskmanagerapi, dependências Spring Data JPA e PostgreSQL Driver), conecte-o ao banco taskmanager e mapeie a primeira entidade. É o que você já fez com Produto no loja, agora no Spring Boot.
Requisitos
  • application.properties com URL, usuário e senha do PostgreSQL, ddl-auto=update e show-sql=true
  • Enum Prioridade (BAIXA, MEDIA, ALTA) no pacote model
  • Entidade Tarefa (tabela tarefas): id, titulo (obrigatório), descricao, prioridade gravada como texto, prazo (LocalDate) e concluida
  • Construtor vazio e construtor (String titulo, Prioridade prioridade), getters e setters
  • Interface TarefaRepository no pacote repository
Solução
# src/main/resources/application.properties spring.application.name=taskmanagerapi spring.datasource.url=jdbc:postgresql://localhost:5432/taskmanager spring.datasource.username=postgres spring.datasource.password=postgres spring.jpa.hibernate.ddl-auto=update spring.jpa.show-sql=true
package br.org.irede.taskmanagerapi.model; public enum Prioridade { BAIXA, MEDIA, ALTA }

Usuario e a Relação 1:N com Tarefa
Básico
Toda tarefa pertence a um usuário, e um usuário tem várias tarefas. Crie a entidade Usuario e mapeie a relação bidirecional 1:N, com Tarefa como lado dono.
Requisitos
  • Usuario (tabela usuarios): id, nome (obrigatório), email (obrigatório e único)
  • Em Tarefa: atributo usuario com @ManyToOne e FK usuario_id obrigatória
  • Em Usuario: List<Tarefa> tarefas com @OneToMany(mappedBy = ...), já inicializada
  • Métodos auxiliares adicionarTarefa e removerTarefa que sincronizam os dois lados
  • Interface UsuarioRepository
Solução
package br.org.irede.taskmanagerapi.model; import jakarta.persistence.*; import java.util.ArrayList; import java.util.List; @Entity @Table(name = "usuarios") public class Usuario { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id; @Column(nullable = false) private String nome; @Column(nullable = false, unique = true) private String email; @OneToMany(mappedBy = "usuario") // lado inverso private List<Tarefa> tarefas = new ArrayList<>(); public Usuario() { } public Usuario(String nome, String email) { this.nome = nome; this.email = email; } public void adicionarTarefa(Tarefa tarefa) { tarefas.add(tarefa); tarefa.setUsuario(this); } public void removerTarefa(Tarefa tarefa) { tarefas.remove(tarefa); tarefa.setUsuario(null); } // getters e setters de id, nome e email; getTarefas() sem setter }
// Tarefa.java — acrescente: @ManyToOne // lado dono (fetch padrão: EAGER) @JoinColumn(name = "usuario_id", nullable = false) private Usuario usuario; public Usuario getUsuario() { return usuario; } public void setUsuario(Usuario usuario) { this.usuario = usuario; }
package br.org.irede.taskmanagerapi.repository; import br.org.irede.taskmanagerapi.model.Usuario; import org.springframework.data.jpa.repository.JpaRepository; public interface UsuarioRepository extends JpaRepository<Usuario, Long> { }

💡 Se a tabela tarefas já tiver linhas da questão 1, o ddl-auto=update não consegue adicionar a coluna usuario_id bigint not null: as linhas antigas ficariam sem valor e o PostgreSQL recusa. Em desenvolvimento, apague as tabelas (DROP TABLE tarefas;) e rode de novo. Repare também que o @OneToMany não gerou nada no banco: a FK inteira vem do lado dono.
3)
CommandLineRunner de Demonstração
Intermediário
No loja, o teste ficava no main. No Spring Boot, use um CommandLineRunner: um bean cujo método run é executado assim que a aplicação sobe. Crie a classe CargaInicial que grava a usuária Ana com duas tarefas e lista as tarefas com o nome da dona.
Requisitos
  • Classe CargaInicial no pacote config, anotada com @Component e implementando CommandLineRunner
  • Repositórios recebidos por injeção pelo construtor
  • Se já houver usuários no banco, não faz nada (para não duplicar a cada execução)
  • Salva a Ana, liga duas tarefas a ela com adicionarTarefa e salva as tarefas
  • Lista todas as tarefas no formato Título (PRIORIDADE) → Nome
Solução
package br.org.irede.taskmanagerapi.config; import br.org.irede.taskmanagerapi.model.Prioridade; import br.org.irede.taskmanagerapi.model.Tarefa; import br.org.irede.taskmanagerapi.model.Usuario; import br.org.irede.taskmanagerapi.repository.TarefaRepository; import br.org.irede.taskmanagerapi.repository.UsuarioRepository; import java.util.List; import org.springframework.boot.CommandLineRunner; import org.springframework.stereotype.Component; @Component public class CargaInicial implements CommandLineRunner { private final UsuarioRepository usuarioRepository; private final TarefaRepository tarefaRepository; public CargaInicial(UsuarioRepository usuarioRepository, TarefaRepository tarefaRepository) { this.usuarioRepository = usuarioRepository; this.tarefaRepository = tarefaRepository; } @Override public void run(String... args) { if (usuarioRepository.count() > 0) return; Usuario ana = usuarioRepository.save(new Usuario("Ana", "ana@email.com")); Tarefa jpa = new Tarefa("Estudar JPA", Prioridade.ALTA); Tarefa pr = new Tarefa("Revisar PR", Prioridade.MEDIA); ana.adicionarTarefa(jpa); ana.adicionarTarefa(pr); tarefaRepository.saveAll(List.of(jpa, pr)); for (Tarefa t : tarefaRepository.findAll()) { System.out.println(t.getTitulo() + " (" + t.getPrioridade() + ") → " + t.getUsuario().getNome()); } } }

Etiqueta e a Relação N:N com @JoinTable
Intermediário
Na aula 04, as tarefas ganham etiquetas ("estudo", "urgente"...). Uma tarefa tem várias etiquetas e uma etiqueta classifica várias tarefas: relação N:N. Mapeie-a com Tarefa como lado dono e atualize a CargaInicial.
Requisitos
  • Etiqueta (tabela etiquetas): id e nome (obrigatório, único, até 50 caracteres)
  • Em Tarefa: Set<Etiqueta> etiquetas com @ManyToMany e @JoinTable para a tabela tarefa_etiqueta (tarefa_id, etiqueta_id)
  • Em Etiqueta: Set<Tarefa> tarefas com mappedBy
  • Métodos adicionarEtiqueta e removerEtiqueta em Tarefa, sincronizando os dois lados
  • EtiquetaRepository e uma CargaInicial com @Transactional que cria "estudo" e "urgente" e as associa às tarefas da Ana
Solução
package br.org.irede.taskmanagerapi.model; import jakarta.persistence.*; import java.util.HashSet; import java.util.Set; @Entity @Table(name = "etiquetas") public class Etiqueta { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id; @Column(nullable = false, unique = true, length = 50) private String nome; @ManyToMany(mappedBy = "etiquetas") // lado inverso private Set<Tarefa> tarefas = new HashSet<>(); public Etiqueta() { } public Etiqueta(String nome) { this.nome = nome; } public Set<Tarefa> getTarefas() { return tarefas; } // getters e setters de id e nome }
// Tarefa.java — acrescente (imports java.util.HashSet e java.util.Set): @ManyToMany // lado dono @JoinTable(name = "tarefa_etiqueta", joinColumns = @JoinColumn(name = "tarefa_id"), inverseJoinColumns = @JoinColumn(name = "etiqueta_id")) private Set<Etiqueta> etiquetas = new HashSet<>(); public void adicionarEtiqueta(Etiqueta etiqueta) { etiquetas.add(etiqueta); etiqueta.getTarefas().add(this); } public void removerEtiqueta(Etiqueta etiqueta) { etiquetas.remove(etiqueta); etiqueta.getTarefas().remove(this); } public Set<Etiqueta> getEtiquetas() { return etiquetas; }
// CargaInicial.java — receba também o EtiquetaRepository no construtor @Override @Transactional // org.springframework.transaction.annotation.Transactional public void run(String... args) { if (usuarioRepository.count() > 0) return; Etiqueta estudo = etiquetaRepository.save(new Etiqueta("estudo")); Etiqueta urgente = etiquetaRepository.save(new Etiqueta("urgente")); Usuario ana = usuarioRepository.save(new Usuario("Ana", "ana@email.com")); Tarefa jpa = new Tarefa("Estudar JPA", Prioridade.ALTA); ana.adicionarTarefa(jpa); jpa.adicionarEtiqueta(estudo); jpa.adicionarEtiqueta(urgente); Tarefa pr = new Tarefa("Revisar PR", Prioridade.MEDIA); ana.adicionarTarefa(pr); pr.adicionarEtiqueta(urgente); tarefaRepository.saveAll(List.of(jpa, pr)); System.out.println("urgente → " + urgente.getTarefas().size() + " tarefas"); }

Revisão de Fetch, Cascade e Boas Práticas
Avançado
Feche a aula 04 aplicando as regras do slide. Ajuste fetch e cascade das relações, implemente equals()/hashCode() com chaves de negócio e reescreva a CargaInicial para gravar tudo com um único save.
Requisitos
  • Tarefa.usuario passa a ser FetchType.LAZY
  • Usuario.tarefas com cascade = CascadeType.ALL e orphanRemoval = true
  • Tarefa.etiquetas com cascade = {PERSIST, MERGE} (nunca REMOVE)
  • equals()/hashCode() por email em Usuario e por nome em Etiqueta
  • CargaInicial: um único usuarioRepository.save(ana) grava usuário, tarefas e etiquetas; depois imprime cada tarefa com o nome da dona e as etiquetas em ordem alfabética
Solução
// Tarefa.java — relações revisadas @ManyToOne(fetch = FetchType.LAZY) @JoinColumn(name = "usuario_id", nullable = false) private Usuario usuario; @ManyToMany(cascade = {CascadeType.PERSIST, CascadeType.MERGE}) @JoinTable(name = "tarefa_etiqueta", joinColumns = @JoinColumn(name = "tarefa_id"), inverseJoinColumns = @JoinColumn(name = "etiqueta_id")) private Set<Etiqueta> etiquetas = new HashSet<>();
// Usuario.java — cascade, orphanRemoval e equals/hashCode (import java.util.Objects) @OneToMany(mappedBy = "usuario", cascade = CascadeType.ALL, orphanRemoval = true) private List<Tarefa> tarefas = new ArrayList<>(); @Override public boolean equals(Object o) { if (this == o) return true; if (!(o instanceof Usuario outro)) return false; return Objects.equals(email, outro.email); } @Override public int hashCode() { return Objects.hash(email); } // Etiqueta.java — mesma ideia, com o nome @Override public boolean equals(Object o) { if (this == o) return true; if (!(o instanceof Etiqueta outra)) return false; return Objects.equals(nome, outra.nome); } @Override public int hashCode() { return Objects.hash(nome); }
// CargaInicial.java — o TarefaRepository e o EtiquetaRepository não são mais necessários aqui @Override @Transactional public void run(String... args) { if (usuarioRepository.count() > 0) return; Etiqueta estudo = new Etiqueta("estudo"); Etiqueta urgente = new Etiqueta("urgente"); Usuario ana = new Usuario("Ana", "ana@email.com"); Tarefa jpa = new Tarefa("Estudar JPA", Prioridade.ALTA); jpa.adicionarEtiqueta(estudo); jpa.adicionarEtiqueta(urgente); ana.adicionarTarefa(jpa); Tarefa pr = new Tarefa("Revisar PR", Prioridade.MEDIA); pr.adicionarEtiqueta(urgente); ana.adicionarTarefa(pr); usuarioRepository.save(ana); // Usuario → Tarefa (ALL) → Etiqueta (PERSIST) for (Tarefa t : ana.getTarefas()) { List<String> nomes = t.getEtiquetas().stream() .map(Etiqueta::getNome).sorted().toList(); System.out.println(t.getTitulo() + " → " + t.getUsuario().getNome() + " " + nomes); } }

💡 Siga o cascade no console: o save(ana) insere o usuário, propaga para a 1ª tarefa (ALL), que propaga para as etiquetas novas (PERSIST), e depois insere a 2ª tarefa. A "urgente" não é inserida duas vezes, porque já está gerenciada. Com Tarefa.usuario LAZY, um tarefaRepository.findAll() não busca mais os usuários. Acessar getUsuario().getNome() fora de uma transação lança LazyInitializationException, e dentro de uma transação, em laço, gera o N+1. A cura definitiva é o JOIN FETCH da aula 05. Por fim, com orphanRemoval, um ana.removerTarefa(pr) dentro de uma transação gera o DELETE da tarefa.
